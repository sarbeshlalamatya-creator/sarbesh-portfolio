My roleDesign system design
Navigation

One menu, three widths.

An admin tool with nineteen pages needs a menu that can get out of the way. The sheet draws the same sidebar five ways, from full labels down to a 52px rail of icons.

Switch between them. The icons never move, so the rail is just the full menu with the words switched off.

Feedback

One status, four places.

Success, warning, error and info each get one soft colour. That colour follows the message from a button to a toast to a full dialog, so a user learns it once.

My reading of the colour, button, toast and dialog sheets together
Dates

Two calendars, one grid.

Nepal runs on two calendars. Offices and colleges date things in Bikram Sambat, while software and email default to the Gregorian one. The system gives both the same component.

Click any two days to select a range.

GregorianMarch 2025, English day names.

Bikram SambatBaisakh 2081, Nepali day names and Devanagari numerals.

  • Saturday is redSaturday is Nepal's weekly holiday, so it's the day marked red in both versions.
  • Same shapeHeader, arrows, seven columns and the range fill are identical. Only the labels change.
  • A day stepper tooFor single-day screens there's a small "‹ Sunday ›" control instead of the full month.

Both calendars are rebuilt in code from the sheet, using the real dates for each month.

Layout

The page is a table.

Almost every AttendEase screen is a list of students, logs or devices. So the system treats the table as the page: tabs and filters above it, actions inside it, pagination pinned below it.

    Foundations

    Purple for doing, grey for everything else.

    Two purples carry every action. A ladder of greys and lavender tints handles surfaces and text, and four pastels handle status. Click a swatch to copy it.

    Four button types, each with and without an icon, in default, hover and disabled rows.

    Twelve pastel tags, for labels that need to be told apart rather than ranked.

    Looking back

    What I'd tighten next.

    The menu, the shared status colours and the two calendars do real work. These are the next fixes.

    1. Name the palette.The colour sheet lists 23 swatches by hex only, and #6B7280 and #404040 appear twice. Named tokens such as "text-muted" or "surface-tint" would stop that drift.
    2. Darken text on the pastels.The filled status buttons put white text on soft fills. White on the success green #87D89D is about 1.7:1, far below the 4.5:1 small text needs.
    3. Let actions follow the status.Error and warning dialogs still use a green "Okay" or "Continue". A risky action should carry the warning or error colour, not success.
